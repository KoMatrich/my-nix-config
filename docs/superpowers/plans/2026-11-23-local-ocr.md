# Local OCR Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Install fully local PaddleOCR-VL-1.6 inference and expose last-resort image/PDF text-extraction tools to every OpenCode model.

**Architecture:** A lazy Python CLI loads a pinned CPU model only when OCR is needed. Poppler extracts native PDF text and renders only pages needing OCR; Home Manager installs a global plugin with two tools that call the CLI through an absolute path.

**Tech Stack:** NixOS/Home Manager, Python 3, PyTorch, Transformers 5, Pillow, Hugging Face Hub, Poppler, OpenCode 1.19 plugin API, JavaScript.

**Spec:** `docs/superpowers/specs/2026-11-23-local-ocr-design.md`

## Global Constraints

- Use model revision `132c45f52c0a26ed5a6b2f6bd8e3985794cc27dd` and CPU-only deterministic inference.
- No hosted OCR, shell interpolation, persistent daemon, automatic attachment hook, or GPU contention.
- First use may download 1.9 GB; subsequent model loads must work offline from `/home`.
- Delete temporary PDF page images and preserve selected 1-indexed page order.
- Do not commit or perform Git mutations unless separately requested.

## Review Focus

- PDF page-range parsing and form-feed handling: Task 1 pins valid, invalid, blank, and partial-text cases with unit tests.
- PDFs with usable text layers: Task 1 tests the usability decision and Task 3 proves no model is needed for native PDF text.
- Paths and failures reaching a shell: Task 2 checks `execFile` with an absolute executable and review checks path/error handling.
- Model unexpectedly using the GPU or network after caching: Task 3 checks CPU operation and reruns with offline variables.
- OpenCode version/API mismatch: Task 2 syntax-checks the plugin and Task 3 loads it in OpenCode before final verification.

### Task 1: OCR CLI and PDF decision logic

**Files:**
- Create: `pkgs/local-ocr/local_ocr.py`
- Create: `pkgs/local-ocr/test_local_ocr.py`

**Interfaces:**
- Consumes: local image/PDF paths; optional PDF page specification such as `1,3-5`; pinned Hugging Face snapshot; Poppler binaries.
- Produces: `local-ocr image PATH` and `local-ocr pdf PATH [--pages SPEC]`, with extracted text on stdout and progress/errors on stderr.

- [ ] **Step 1: Write failing unit tests**
  Cover `parse_page_spec`, page-range validation, `split_pdf_text` form-feed/blank-page behavior, and usable native-text detection. Run the tests and confirm they fail because `local_ocr.py` does not exist yet.
- [ ] **Step 2: Implement the CLI**
  Lazily download/load the pinned model, force CPU inference, decode only generated tokens, and cap each image/page generation. Extract native PDF text per page, render pages lacking usable text into an automatically removed temporary directory, and format results with `--- Page N ---` markers.
- [ ] **Step 3: Run unit and error-path tests**
  Expected: all pure-logic tests pass; missing files, malformed page ranges, and out-of-range pages exit nonzero without trying to download the model.

**Interfaces:**
- Consumes: the Task 1 CLI and installed OpenCode 1.19.x `@opencode-ai/plugin` API.
- Produces: user command `local-ocr`; global tools `ocr_image({ path })` and `ocr_pdf({ path, pages? })`.

- [ ] **Step 1: Capture failing pre-change checks**
  Confirm `local-ocr` is not installed and the Home Manager OCR plugin path has no current definition.
- [ ] **Step 2: Package and wire the tools**

- [ ] **Step 3: Validate package and plugin structure**
  Run the unit tests through the Nix package check phase, `node --check pkgs/local-ocr/opencode-plugin.js`, and evaluate the resulting Home Manager package/file entries. Expected: all pass and only the two intended tools are declared.
